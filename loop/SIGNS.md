# SIGNS.md: lessons learned (one imperative line each)

- Never run compound shell commands that touch paths outside the repo except via the English clone path in CONFIG.yaml; keep Bash calls simple (one command each).
- If the sandbox denies `tar -x` of the English tree into the repo, block P0-002 at once; do not retry variants or hand-copy files.
- Compound Bash (&&, ;, redirects mixed with other commands) is denied; a single pipeline `git -C <english_clone_path> archive <sha> | tar -x -C <repo> --exclude=.gitignore` is allowed. Edit files with Edit/Write, not shell.
- Import the English tree with: git -C <english_clone_path> archive <sha> | tar -x -C . ; keep this repo's own .gitignore entries and loop/, translation/, ralph-kit-es/ and the plan file intact.
- Never extract the English tree with `--exclude=.gitignore` (it drops nested ones); `tools/inventory.py --check` compares the file set to the pinned SHA and catches this.
- Run `python3 -I tools/test_*.py` for tool tests; keep Bash calls single-command when possible, tools in tools/ read files with `with open`.
- Do not write to paths outside this repo or the English clone (for example /tmp): such writes are denied in dontAsk mode. Use translation/work/ (git-ignored) for scratch files.
- Do not use $?, $(...) or backticks in Bash calls; they are denied. Run one simple command per call and read its output instead.
- Use the project virtualenv (.venv; already first on PATH). pip and npm installs are allowed (Jim approved installs in chat); install into .venv only, never globally, and record each new dependency in requirements-es.txt.
- Never use $PIPESTATUS, `echo` or pipes with `tail` in Bash calls to capture exit codes; write a small tool in tools/ that records them (see tools/baseline.py) and run it as one command.
- Write scripts with the Write tool, never shell heredocs (denied); change a seed-queue task status with `python3 tools/seedtask.py <id> <status> [notes]`.
- Run `python3 tools/next_task.py` to pick (exit 0 = TASK, 1 = NONE-BLOCKED, 2 = NONE-WAITING, 3 = NONE-COMPLETE); never use `&&`, `;` or `echo $?` in Bash calls, they are denied.
- After editing translation/glossary.es.yaml run `python3 -I tools/glossary_check.py`; quote YAML scalars containing `: ` and never write `banned: [a, "b" text]` (invalid flow sequence).
- Append to loop/*.md with Edit anchored on the last line; `cat >> file <<EOF` is denied (heredoc).
- After editing translation/prompts/ or translation/schemas/ run `python3 -I tools/prompt_check.py`; it validates every JSON example in the prompts and every sample row, so update both together.
- Compare frozen files by git blob content: .bat files check out as CRLF here (.gitattributes), so raw working-tree hashes of gradlew.bat differ by design; use tools/lock_code.py --verify, never plain sha256sum -c.
- After editing lessons/book/locale/es.yaml run OK locale phases 1 to 5 (lessons/book/locale/es.yaml); to change the acronym edit only its acronym and phases blocks, never the Mermaid node IDs W E I R D.
- The Write and Edit tools decode \uXXXX escapes and normalize NBSP and combining marks; build special characters with chr() in a script under translation/work/ and run `python3 -I tools/fixture_check.py` after touching tests/fixtures/.
- After adding a new directory of Spanish-owned files, add its prefix to OWNED_PREFIXES in tools/inventory.py and run `python3 tools/inventory.py --check` before committing.
- Build masking regexes with named groups (never numbered backreferences) and unmask in one non-recursive pass; run `python3 -I tools/test_mask.py` after touching tools/mask.py.
- Add every new locale key to BOTH lessons/book/locale/en.yaml and es.yaml in the same commit, then run `python3 -I lessons/book/locale/catalog.py --check es en` and `python3 -I tools/test_catalog.py`; never name a package `locale` (it shadows the stdlib), import catalog.py by putting its directory on sys.path.
- Tools run as `python3 -I` do not see sibling modules: put HERE on sys.path before `import mask`/`import segment`; after touching tools/segment.py run `python3 -I tools/test_segment.py` and `python3 -I tools/segment.py --t0`.
- After touching tools/apply.py or the PO layout run `python3 -I tools/test_apply.py` and `python3 -I tools/apply.py --identity`; PO entries are keyed by msgctxt = segment id, and macros must expand in msgstr before unmask.
- After touching tools/mermaid.py or the Mermaid path of tools/segment.py run `python3 -I tools/test_mermaid.py`; the extractor fails closed on unquoted labels, click and multi-line accDescr, so a new diagram style needs a new rule and a test, never a looser regex.
- After touching tools/invariants.py run `python3 -I tools/test_invariants.py`; style checks (I7, I9, I10, I12, I14) must read the MASKED target with placeholders stripped, never the restored text, and a waiver is only an exception-register row naming the segment and the invariant.
- After touching tools/verify.py run `python3 -I tools/test_verify.py`; the English side of every check comes from the pinned clone, and tests must never start the English repo gates (`--release` without `--no-gates` takes many minutes).
- Run `python3 -I tools/verify.py --fast` before every commit; a localized tooling file must be added to translation/tooling-allowlist.txt in the same commit or I13 fails.
- Name catalog keys for fixed bold lead-ins `lead_in_*` (invariant I11 only enforces those), and when localizing a tooling file add its row to translation/tooling-allowlist.txt in the same commit; append with Edit, heredocs are denied.
- After a Spanish heading changes run `python3 -I tools/anchors.py --generate`, remap links with `--remap FILE` and run `--check`; commit translation/anchors.json with the heading change, and keep headings NFC so the build slug equals the GitHub slug.
- Keep `slug()` in lessons/book/study_guides.py, build.py and cs.py a verbatim copy of each other (tools/test_anchors.py execs them); normalize text at the call site (nfc), never inside slug().
- Translate "What the challenge does" in lessons/intro.md as exactly the catalog value study_guides.challenge_heading, because SHARED_CHALLENGE links to its slug.
- Before refactoring a generator, hash its English output with translation/work/cs_snapshot.py (sha256 of generate_all) and require the same hash after; heredocs (`python3 - <<EOF`) are denied, so edit with the Edit tool.
- When testing a Spanish generator over the still-English READMEs, call diagrams.set_language("en") after cs.set_language("es") so the Program Flow sections parse; generate_all lists a block page only when its text differs, so fill missing ones from disk before comparing.
- Store a catalog number that differs by language (a word limit) as quoted text and parse it in code: catalog.py requires integer values to be equal in en.yaml and es.yaml.
- After running any lessons/book test, run `git status --short` and `git checkout -- lessons/book/__pycache__/build.cpython-312.pyc`: that tracked, locked .pyc gets rewritten when build.py is imported.
- Edition identity (repo URL, branch, stems, title, es-419, UUIDs) lives in catalog block identity.*; change a Spanish value there and recompute the three metadata identifiers with repo_links.publication_uuid in the same commit, or test_repo_links.py fails.
- Translate the README, guides and APL pages so they match the patterns in catalog blocks editorial.* and sentinels.* (count line, assurance tally sentence, APL phrases, Mermaid label texts); run `env BOOK_LANG=es python3 lessons/book/test_editorial.py` after stage 4, where all its tests must pass.
- Add a plan 10.2 negative case as a Fixture in tools/negative.py (mutate the finished file with `after=` when the target is a protected token, since the PO layer restores code from the English mask) and run `python3 -I tools/negative.py`; a fixture that returns no problems means the gate is disarmed, so fix or add the gate, never the fixture.
- Re-run `python3 -I tools/scratch_proof.py` (about 5 minutes; start it with run_in_background and poll with `timeout 280 tail -f <output file>`, never `until`/`sleep` loops) after any change to the allowlisted tooling or the catalog, and keep the metadata YAMLs out of the layer.
- Check literal phase letters and the literal acronym on the PO msgstr BEFORE macro expansion (check_segment raw=), and ambiguity on the expanded text; a colliding letter after "fase" needs its name (phase_lint.py).
- Keep canary data (rate, ids, fragments) out of every public review file (packets, manifest.json, EDITION-FACTS.md, bundle); after touching tools/jury_packet.py run `python3 -I tools/test_jury_packet.py` and `python3 -I tools/test_jury_ingest.py`, and check quotes in ingest against the text as shown (units.index.jsonl), never the original Spanish.
- When translate.py leaves needs-revision entries, first ask whether the CHECK is wrong (plural, verb vs noun, identifier in a Mermaid label); narrow it with a test and a provisional decision, else waive one segment in translation/exception-register.jsonl; then `apply.py FILE --write` and `verify.py --fast`; the translator reuses a glossary-banned word only when the English asks for it.
- Translate a file with `python3 -I tools/translate.py FILE.md --task-id ID [--limit K]` (PO saved after each segment; rerun resumes, `--from N` jumps, `--redo-fuzzy` retries needs-revision entries); never add keys to ledger rows (closed schema), and use `mask.PH_RE.finditer` and `m.group(0)` because `findall` returns tuples.
- A link title that is an English article name ("Tail call") is translated, not kept: re-run `translate.py FILE --task-id ID --redo-fuzzy` once before waiving; check I7 needs-revision for gender (recursiva) or number first.
- Never run translate.py on a file after `apply.py --write` has made it Spanish (it re-segments the Spanish and appends orphan PO entries, now refused); on a cut run `git checkout -- FILE` first, then rerun to resume; `anchors.py --check` is a P5-002 gate, and `--remap` must never touch generated pages (lessons/languages/*.md, I13).
- After translating a file that names phases, run its own build check (`env BOOK_LANG=es python3 lessons/curriculum/build.py --check`) as well as verify --fast; edit a PO by hand only on a restored English file (`git checkout -- FILE`, then `apply.py FILE --write`), and use the exact edition title from the catalog (identity.book_title), never a translator rendering.
